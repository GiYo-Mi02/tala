# SSS E-1 print alignment in 0.3.1

The supplied E-1 screenshot shows the SS number, name and date visible in the photo, with green regions displaced from their printed boxes. The review error came from the pre-OCR alignment check. Version 0.3.0 positioned the regions from the bounds of the corrected paper and checked those bounds against the original Letter ratio. Fit-to-page printing, added margins, and a camera crop that includes background can change the printed layout's position within those bounds.

Version 0.3.1 matches printed features against the bundled E-1 reference for the selected sheet. OpenCV estimates a perspective transform with matches spread across the printed layout. The transform aligns the captured pixels to the template before previewing the field boxes or starting OCR. The bundled reference supplies coordinates only. The displayed pixels, typed values, and OCR still come from the captured photo. The app continues to check the photo for blank or dark capture and surfaces warnings for small text. [OpenCV feature matching and perspective alignment](https://docs.opencv.org/4.x/d7/dff/tutorial_feature_homography.html).

Review offers zoom, a toggle for the answer boxes, and manual frame alignment on the original photo. When automatic matching fails, mark the frame corners using the top rule above **PART I** and the bottom border of the last SSS table. The resulting preview shows the boxes before you start OCR. A readable photo can also be saved for manual entry. To recover a previous capture, open its SSS draft and select **Align saved photo**. A photo saved without alignment shows the full source for review. The default BEEF capture flow uses its existing alignment.

Android fixture tests use the same filled E-1 source images for both sheets and place those pages in differently shaped, shaded, perspective-shifted frames. Both automatic and manual alignment are exercised. The automatic results put the expected surname back in the correct crop on both sheets, and ML Kit actually returns `ALVAREZ`. The tests also reject a blank image and cross-page reference matches. This measures registration and representative OCR on simulated photos. The screenshot is a rendered review view, and its original camera file and physical A53 measurements were unavailable.

All 143 host tests, TypeScript checks, and six Android version checks passed. The [first native run](evidence/sss/registration-native-tests.xml) passed 21 of 22 checks, including the registration cases. The camera lifecycle check required the emulator's virtual rear camera and [passed after enabling it](evidence/sss/registration-camera-rerun.txt).
