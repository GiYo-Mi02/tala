# PostgreSQL data dictionary

The [migration](../../apps/backend/migrations/0001_foundation.sql) defines exact nullability, defaults, checks, indexes, and triggers. Times are `timestamptz` and the API emits UTC ISO 8601 strings. Template keys are textual, submission and image identifiers are UUIDs, and OCR and identity values are strings. The [crow’s-foot ERD](erd.md) shows the relationship cardinalities.

## Users and sessions

- **`users`.** `id uuid` is the primary key. `email text` is unique and lowercase. `password_hash text` stores the salted scrypt result. `role user_role` is ENCODER, VERIFIER, or ADMIN. `active boolean` controls sign-in and request access. `created_at timestamptz` records provisioning.
- **`sessions`.** `id uuid` is the primary key. `user_id uuid` references `users.id`. Unique `access_hash text` and `refresh_hash text` hold SHA-256 credential digests. `mode text` is native or browser. `access_expires_at` and `refresh_expires_at` set token expiry. Nullable `revoked_at` records logout or deactivation. `created_at` records initial sign-in. The latter four columns are `timestamptz`.

## Template definitions

- **`document_templates`.** Composite primary key `(id text, version integer)` pins a revision of a form. `name text` is the display label and `metadata jsonb` holds source and template-level rules. Seed commands insert known versions idempotently. Publish changed capture or field rules as new versions and add version-specific validation.
- **`template_pages`.** Composite primary key `(template_id text, template_version integer, page_number integer)`. The first two columns reference the template version. `display_order integer` is unique within that version, `label text` names the slot, `capture boolean` allows image intake, and `required boolean` marks an unconditional capture slot. Conditional pages are described in template metadata.
- **`template_fields`.** Composite primary key `(template_id text, template_version integer, field_key text)`. Adding `page_number integer` forms a unique key that also ties field values to page geometry. The template and page tuple references `template_pages`. `label text`, `data_type text`, and `display_order integer` drive rendering. `rules jsonb` holds required, mode, normalized ROIs, choices, range, and conditional metadata where available.

## Submissions and evidence

- **`submissions`.** `id uuid` is the server primary key. `client_submission_id uuid` is stable and unique per `owner_id uuid`, which references the encoder account. `template_id text` and `template_version integer` reference the exact form version. `captured_at` is the handset capture time, `received_at` and `updated_at` are server timestamps, and nullable `completed_at` serves as the acknowledgment time. `status submission_state` tracks intake and review, and `revision integer` provides optimistic concurrency checks. Nullable `reviewer_id uuid` references the assigned verifier.
- **`document_pages`.** Primary key `(submission_id uuid, page_number integer)`. `template_id text` and `template_version integer` enforce both the matching submission template and the valid template slot. `image_id uuid` is the accepted local capture ID, unique within the submission. `object_key uuid` is a private unique storage name. `mime_type text`, `byte_size integer`, `width integer`, `height integer`, `sha256 text` and `uploaded_at timestamptz` describe the committed file. A stored row represents a complete upload. A missing row leaves the slot incomplete.
- **`field_values`.** Primary key `(submission_id uuid, field_key text)`. `template_id text`, `template_version integer`, and `page_number integer` verify both the owning submission and the mapped template field. Nullable `source_image_id uuid` references the accepted image in that exact submission and slot. Nullable `ocr_original text`, `ocr_confidence double precision`, and `ocr_metadata jsonb` preserve recognition evidence, with bounding rectangles and engine information where available. `mobile_value text` and `mobile_confirmed boolean` preserve the encoder’s snapshot. Nullable `review_value text` holds the latest correction and nullable `final_value text` holds the frozen result. A trigger protects the intake snapshot and previously written final values.

## Reviews, retries, and audit

- **`verification_records`.** `id uuid` is the primary key. `submission_id uuid` and `verifier_id uuid` reference the submission and reviewer. `outcome text` is CLAIM, CORRECT, VERIFY, RETURN, REJECT, or FINALIZE. Nullable `notes text` describes the decision and `created_at timestamptz` timestamps it. `revision integer` is unique per submission.
- **`verification_changes`.** Primary key `(verification_id uuid, field_key text)`. `submission_id uuid` participates in foreign keys to the review event and the submission field. `value text` is the correction at that revision. Review notes and changes should be treated as sensitive record data.
- **`sync_operations`.** Primary key `(actor_id uuid, idempotency_key uuid)` scopes retries to a user. `submission_id uuid` references the submission and provides its client UUID through a join. `operation text` and `request_sha256 text` identify the canonical request. `response_status integer`, `response_revision integer`, and `response_state submission_state` preserve the committed acknowledgment. `created_at timestamptz` records when it committed. A rolled-back request leaves no success record, and the absence of a row permits retry.
- **`audit_logs`.** `id bigint` is a generated primary key. Nullable `actor_id uuid`, `target_user_id uuid`, and `submission_id uuid` reference their associated rows. `action text`, `details jsonb`, and `created_at timestamptz` record operational evidence such as outcome, revision and field IDs. An append-only trigger blocks updates, deletes and truncation. Passwords, refresh credentials, scanned bytes, and raw field values stay out of audit metadata.
